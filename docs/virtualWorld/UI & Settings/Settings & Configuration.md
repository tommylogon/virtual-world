# Settings & Configuration

## What you can do

Tune the engine without editing code. Settings covers three different things in
three different places: the **engine's numeric constants** (light, heat, sound - 
see [[UI & Settings/Engine Config|Engine Config]]), the **browser-side
preferences** (API keys, model, dedicated memory worker, embeddings, graph physics),
and the **scenario and app saves**. Change one and it persists; change the engine
constants and they apply live.

VirtualWorld's settings are managed through a combination of backend route handlers,
a frontend `ConfigManager` with IndexedDB persistence, a centralized schema
(`CONFIG_SCHEMA`), and a clean MVC settings view (`SettingsView`).

## Settings Architecture

### Backend Routes (`routes/settings.py`)

The `register_settings_routes()` function registers all settings-related API endpoints:

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/settings/ghost_mode` | Get ghost mode status |
| POST | `/api/settings/ghost_mode` | Toggle ghost mode on/off |
| GET | `/api/settings/narration` | Get narration mode |
| POST | `/api/settings/narration` | Set narration mode (`none`/`player`/`ai`) |
| GET | `/api/settings/time_per_tick` | Get minutes per game tick |
| POST | `/api/settings/time_per_tick` | Set minutes per game tick |
| GET | `/api/settings/engine_config` | Get live engine tuning constants + schema (task-304) |
| POST | `/api/settings/engine_config` | Save engine tuning overrides |
| POST | `/api/settings/engine_config/reset` | Restore engine tuning defaults |
| POST | `/api/debug/save_log` | Save a run log file for debugging |
| GET | `/api/debug/state` | Compact debug dump of world state |
| POST | `/api/path` | Find path between two areas |
| POST | `/api/embeddings` | Generate text embeddings |

## Settings Modal UI & MVC Architecture

The Settings panel (`static/js/ui/settings-view.ts` and `templates/index.html`) implements a decoupled MVC architecture:

1. **Model (`ConfigManagerImpl` & `CONFIG_SCHEMA`)**:
   - Holds pure configuration state without direct DOM element queries.
   - Manages persistence to IndexedDB (`storage.js`) and profile persistence.

2. **View (`templates/index.html`)**:
   - Organizes configuration into five coherent tabs.
   - Binds inputs declaratively using `data-config="fieldName"`.
   - Free of inline micro-controllers mutating the state store.

3. **Controller (`SettingsView`)**:
   - `SettingsView.populateForm()`: Reads `config` and populates `[data-config]` inputs and range value chips.
   - `SettingsView.readForm()`: Scans modal inputs and coerces types based on the schema, feeding `config.saveFromForm()`.
   - `SettingsView.testConnection()`: Diagnostic chat ping for the Primary LLM.
   - `SettingsView.testMemoryConnection()`: Diagnostic ping for the Dedicated Memory Worker with live latency measurement.
   - `EmbeddingClient.test()`: Diagnostic vector calculation for the Embedding Model.

### The Five Modal Tabs

#### 1. Connection (`tab-connection`)
Consolidates all network model connections with diagnostic parity:
- **API Connection**: Base URL, API Key, Model Picker (search, filter chips, model refresh), and Main Test Connection button.
- **Dedicated Memory Model (Task-909)**: Defaults enabled to localhost LM Studio (`http://localhost:1234/v1`, format `lmstudio`, model `lmstudio-community/lfm3-1.7b`), quick-pick dropdown for fast 1-3B models, and Dedicated Test Connection button with latency display.
- **Embedding Model**: Semantic memory toggle, API base URL, model name, vector dimensions, and Embedding Test button.

#### 2. Agent Settings (`tab-agent`)
LLM parameters and execution limits:
- Temperature slider (0.0 to 2.0 with live float readout).
- Hard max tokens limit (API cutoff).
- Soft max tokens limit (system prompt instruction).
- Rate limits: Requests per minute (RPM) and Tokens per minute (TPM).

#### 3. Behavior & Automation (`tab-automation`)
Runtime agent loop options and simulation rules:
- **Agent Behavior**: Reactive mode (3-phase think->act->react), streaming tokens, thinking mode & effort, local thinking suppression, raw LLM request/response capture, end-of-turn memory generation, API format, show LLM logs, manual response mode, auto-generate appearance descriptions, auto-retry invalid actions, structured output (JSON schema).
- **Ghost Mode**: Dead characters continue to act as ghosts.
- **Content**: Mature content opt-in (pleasure/arousal subsystem).
- **Game Clock**: Minutes per tick (game minutes elapsed per agent step, default 5).

#### 4. Graph (`tab-graph`)
In-place vis.js graph physics and layout tuning:
- Spring lengths (contents length), spring constants (snappiness), gravitational repulsion (spread), overlap guard (strength, min distance, max distance, stray pull), node sizes, edge widths, arrows, damping, solver (Force Atlas 2, Barnes-Hut, Repulsion), and camera focus zoom.
- All controls tune the graph in place without rebuilding or resetting positions, matching the Graph canvas Tune popover.

#### 5. Engine Config (`tab-engine-config`)
Server-side engine constants loaded via `EngineConfigView` from `/api/settings/engine_config`:
- Sound propagation barriers, noise levels, and speech distances.
- Heat propagation base rate and maximum temperature deltas.
- Light spill factors.
- Persisted to `data/engine_config.json`.

### Provider Profiles

The settings modal supports **named profiles** for switching between LLM configurations. The default profile is **LM Studio (Local)** (`http://localhost:1234/v1`, model `glm-4-9b-0414`).
Built-in profiles include:
- LM Studio (Local) - default (local, model `glm-4-9b-0414`, memory model enabled)
- Groq (`https://api.groq.com/openai/v1`, `llama-3.3-70b-versatile`)
- Mistral (`https://api.mistral.ai/v1`, `mistral-large-latest`)
- NVIDIA NIM (`https://integrate.api.nvidia.com/v1`, `llama-3.3-70b-instruct`)
- DeepSeek / DeepSeek (V4 Pro)
- OpenRouter

Profiles are managed via:
- `config.getProfiles()` - list all profiles
- `config.applyProfile(name)` - load a profile's settings
- `config.saveProfile(name, data)` - save to a profile
- `config.saveProfileFromCurrent()` - update current profile
- `config.saveProfileAsNew()` - create new profile from current settings
- `config.deleteProfile_()` - remove a profile

Profile data includes: `apiKey`, `apiBase`, `model`, `streaming`, `showLogs`, `turnBased`, `turnOrder`, `apiFormat`, `memoryModelEnabled`, `memoryApiBase`, `memoryApiKey`, `memoryModel`, `memoryApiFormat`.

## Save/Load Configuration

### Saving (`config.saveFromForm()`)

1. Reads modal form values via `SettingsView.readForm()`.
2. Persists values to IndexedDB via `config.save()`.
3. Syncs updated credentials to the active profile.
4. Updates `VW.llm` configuration via `config.toLLMConfig()`.
5. Logs "Settings saved." to the event stream.

### Loading

Initial values are loaded from IndexedDB on page load via `ConfigManager._init()` -> `_loadFromStorage()`, falling back to `CONFIG_SCHEMA.*.default`.

## Where it lives

- `static/js/config.ts` (`ConfigManager`, `CONFIG_SCHEMA`, IndexedDB persistence)

- `static/js/ui/engine-config-view.js` (Engine Config tab view)
- `tools/unit/test_graph_toolbar.js` & `tools/unit/test_graph_tuning.js` (Settings modal graph tab contracts)
