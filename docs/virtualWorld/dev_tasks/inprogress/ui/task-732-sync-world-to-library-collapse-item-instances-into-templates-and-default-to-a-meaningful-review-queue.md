# task-732: Sync World to Library: collapse item instances into templates and default to a meaningful review queue

**Filed:** 2026-10-07
**Related:** bug-526, task-724

## Goal

Make Sync World to Library answer 'which authored changes deserve to become library templates?' instead of 'sync everything'. Collapse item instances into one template row, exclude generated and unchanged by default, and lead with a reviewable changeset rather than a silent whole-world batch. A batch should be a handful of decisions, not hundreds.

## Measured (2026-10-07, kraktooth_goblin_camp)

```
item nodes: 152     distinct names: 132   (26 nodes in duplicate-name groups: 12x wild_berries, 5x Frost-Crusted Berry Bush, ...)
area nodes: 223     generated (cell): 222
Sync dialog at the time: 633 new / 167 differ
```

The list is ~99% noise and the primary button says "dump it all in". Fixing the
button is not the 10x; fixing what is in the list and what the button means is.

## Principle

Sync should answer "which of my **authored** changes deserve to become library
templates?" — not "sync everything?". Those are different questions; conflating
them is why the counts read 633.

## Levers, ranked

1. **Collapse instances → one template.** Group item nodes by identity and offer
   one row ("12 wild_berries → one entry"). *Landed (see below).*
2. **Default to a meaningful review queue.** Show authored/edited/differing by
   default; hide generated and unchanged. Sync All becomes the escape hatch.
3. **Review → apply.** Per-entity old→new field diff with checkboxes, then
   "apply selected", plus a dry-run header ("would create 4, overwrite 2, skip
   222 generated, 131 unchanged"). Git-like: the library stores one JSON file per
   entry, so the diffs are already there.
4. **Undo.** Snapshot before a batch (backup dir, or lean on git). A destructive
   batch with no undo is why silent overwrite is scary.
5. **Provenance + a synced-content hash.** Stamp origin
   (`authored`/`generated`/`imported`) and a hash of what was last synced, so
   "differs" is a cheap hash check and "changed since last sync" is real.
6. **Link placed nodes to their template** (`library_id`) after syncing so the
   next sync recognizes them and never re-adds. The primitive already exists.
7. **Filters by mental model:** by area ("everything in the Fisherman's Hut"), by
   tag, by type, "authored only".

## Landed (2026-10-07)

`static/js/world-sync.ts`:

- `_group()` collapses entities into `SyncGroup[]`: items group by
  `library_id || slug(name)`; ways/areas/characters stay one row each (they are
  distinct places/people). A group's status is the worst of its members, and it
  is `generated` only when every member is.
- The list, summary, `openEntityByIndex`, `viewDiffByIndex`, and `syncAll` now
  operate on groups; a group renders `label ×N` and `Sync All` saves one entry
  per group (its representative, preferring a non-generated member).
- Combined with bug-526's tab scoping and generated-skip.

`npm run build:ts` clean.

## Open question — the real design call

Grouping needs a **stable template key**: two nodes are "the same" when they
share a `library_id`, else a name+tags slug. "12 wild_berries" are one template;
"Wash Spot ×2" might be two distinct fixtures. Anchor on `library_id` first, then
a name+tags slug, and **ask when ambiguous** rather than guess.

## Remaining

- Levers 2–7 above. The biggest next one is #2 (hide unchanged/generated by
  default) and #3 (review/apply with a dry-run).
- A unit test for `_group()` (grouping, worst-status, generated-only) — the
  module currently has none.
