# Vault pass: link by what's connected, one page per feature, real Obsidian semantics

**Goal.** Turn the vault from "an index with islands" into a connected knowledge graph: every feature in the Feature Map gets a real page, every curated note gains a `Connected` section and namespaced tags, Obsidian affordances (callouts, heading links) get used where they actually help — and new guards keep it from rotting back.

## Defaults I'm proceeding on (you didn't answer; each is cheap to change)

1. **New `docs/virtualWorld/Features/` folder, one page per Feature Map row** (~76). System pages stay the deep docs; nothing moves.
2. **Namespaced tags**: `#system/<domain>`, `#surface/editor|in-game|lens|api`, `#area/<task-area>`, `#status/wired|authored|planned|unwired` (mirrors the Map's own status vocabulary).
3. **Curated docs only** (the 80 human-written pages). The 805 task files are left alone — they carry structured frontmatter the tools already parse.
4. **Yes, extend the existing tools** with guards, wired into `npm run precommit`.

## Phase 1 — `Features/` pages, one per row

`tools/feature_pages.py` with `--scaffold` (creates missing pages, **never overwrites**) and `--check` (every Map row resolves to a page; every page has its required sections; no orphan pages). Template per page:

```markdown
---
type: feature
feature_id: 22
status: wired
tags: [system/memory, surface/in-game, status/wired]
---
# Memory
**What you can do:** What a character remembers, and recall by need.
## How it works
One honest paragraph + `[[Memory System]]` (the deep doc) and `[[Memory Dynamics]]`.
## Where it lives
`engine/memory_dynamics.py`, `routes/memories.py`, …
## Connected
Sibling features · systems · dev tasks that touch it.
> [!note] Status — wired. Last verified 2026-10-05.
```

Scaffold mechanically, then enrich by domain in batches (memory/combat/items/world first). Filenames are the feature name, de-duplicated against existing basenames.

## Phase 2 — Tags on the curated docs

Controlled vocabulary in one place (`tools/doc_tags.py` owns it), applied to the 80 curated docs + the new feature pages: every doc gets `tags:` frontmatter with at least one `#system/…`, plus `#surface/…` where applicable and `#status/…` where the Feature Map states one.

## Phase 3 — `Connected` sections (the "link by what's connected" ask)

Every curated doc gains a `## Connected` block built from **relations that already exist**, not invented:
- Feature Map rows whose `Docs` point at this page.
- **The 96 task files that already carry `wiki: [[…]]` frontmatter** — those relations exist today and are surfaced nowhere.
- Systems ↔ features both directions; module `@docs` pointers from the module index.
Then bring `_Index.md` up to date (adds the ~35 curated files it misses, including `Memory Dynamics.md` and the new `Features/` index).

## Phase 4 — Obsidian affordances + repairs

- Callouts where they carry meaning: status vocabulary → `> [!abstract]`, the Map's unverified/gap sections → `> [!warning]`/`> [!caution]`, feature pages → `> [!note] Status`. (Today: zero callouts in 885 notes.)
- `Connected` links point at **sections** (`[[Memory System#Memory dynamics (task-685)]]`) where those sections exist — today only 4 heading refs exist in the whole vault.
- Repairs: fix the 3 placeholder links; resolve the duplicate-basename problem (inspect `Rules Engine/Temperature System.md` and rename it to what it actually is, then retarget inbound links with the existing `doc_links.retarget_links` — the same function `tasks.py move` already uses).

## Phase 5 — Guards so it can't rot back

- `doc_links.py --orphans [--min-inbound N]` — report curated notes nothing links to (today: 21).
- `tools/feature_pages.py --check` — Feature Map ⇄ page coverage.
- `tools/doc_tags.py --check` — tags ⊆ vocabulary, with a baseline file for today's debt (the pattern `feature_index.py` already uses).
- Wire all three into `npm run precommit`; document them in `AGENTS.md` (Tools) and `docs/design/Developer Tooling.md`; pytest mirrors for the new checks (`tests/test_feature_pages.py`, `tests/test_doc_tags.py`, extending `tests/test_doc_links.py`).
